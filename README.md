# v2.0: Net losing positions/attempts in the rolling budget (November 2026)

**Effective rule:** 3% (or your editable portfolio setting) of tracked CAD realized equity is the rolling risk ceiling. Available new risk = ceiling **minus net losing position/attempt P/L inside the last five NYSE sessions** minus current open-position risk reserves. This change is computational only: existing fills, source broker commissions/FX, positions, journals, cloud data and JSON backups are unchanged; there is no database migration or historical data rewrite.

- Profitable and losing exits from the **same continuous position attempt** offset one another *only while both exits remain within the current rolling window*. Fees are included in each exit's net CAD P/L. Example: 2 options, one +30%, one -30%; the position contributes only its fee-adjusted net loss, not the runner's gross loss.
- A **fresh buy after the position was completely flat** begins another attempt, even if the saved position object or `ideaId` is reused. Independently entered positions—even those with the same ideaId/ticker—never net against each other. Different accounts never net.
- Standalone **manual prior-trade P/L adjustments** remain separate: profits from a different closed trade cannot cancel a losing trade's rolling charge.
- The app still records **gross losing exits** as a visible *diagnostic* in the dashboard, without subtracting them from the rolling ceiling a second time.
- **Open positions retain their risk reserve** after TP1 (on remaining contracts) until fully closed. Account equity still uses all recorded realized gains/losses; it does not treat entry premium as an immediate realized loss.
- **Rolling-window edge:** when an earlier winning partial expires from the five-session window before its losing runner, the net-loss charge can *increase* temporarily even with no new trades. The next-change notice and 10-session forecast now show increases as well as releases. Daily loss tiles allocate the currently charged net loss to losing-exit dates, rather than displaying raw isolated negative fills.
- No automatic Google trading-master or market-master writes, brokerage execution, API orders, or edits to historical trade records. Download a complete JSON backup before substantial changes to any trading app.

## v1.5: equity automatically follows realized profit and loss

- The risk limit is **risk percentage x tracked current equity**, not permanently based on the initial manual principal. Examples: CAD 18,000 at 3% = CAD 540; CAD 23,000 at 3% = CAD 690.
- **Tracked equity = most recent manually confirmed equity checkpoint + net realized CAD profit/loss recorded after that checkpoint.** Realized exits and signed outside-P/L adjustments count; unrealized option value, unconfirmed open P/L and open stress reserves do not change principal. The risk ceiling changes as recorded profits/losses change tracked equity, while rolling realized LOSSES remain charged gross and are never offset by profits.
- **Safe migration:** When opening older v1.4 data, the manually recorded account equity is treated as an existing broker-balance checkpoint. All realized P/L already logged at migration is pinned as included, rather than added again. The app will not silently reprice historic accounts.
- **Manual reconcile / deposits / withdrawals:** Settings shows the computed live equity. Change that figure to the broker realized-equity equivalent (excluding unrealized gains/losses on still-open options) and save to create a dated balance checkpoint, with prior checkpoints retained in the JSON/cloud record. Saving unrelated account rules does *not* reset the checkpoint. This is not a live broker balance feed: new trades must be imported, and actual CAD P/L/FX should be verified with IBKR.
- **Backfilled trades:** If a later import brings historical realized trades that had already been included in the broker account balance you manually entered, use the equity setting to re-checkpoint against the broker and avoid counting the result twice. Imported records are not deleted.

A later authenticated cloud database/sync service would be needed for genuinely automatic cross-device persistence; no fake cloud-sync toggle is shown here.
- **IBKR data limitations:** The sample export has no execution ID, no trade idea, no underlying exit price, no confirmation of report timezone, and no CAD execution FX. Fills are identified by account/option/side/date/time/quantity/price/fees/NetCash, plus an occurrence index when printed rows are identical. Distinct fills that print **exactly identically** are fundamentally ambiguous: the importer flags this. Review them rather than relying on blind automation. If the same contract is traded in more than one independent idea, that grouping may also need manual reconciliation. Source rows that cannot be matched safely remain in the **unreconciled inbox**; they do not enter the budget or generate fabricated realized P/L.
- **Imported non-swing options:** This is a swing-budget ledger, not a complete IBKR tax statement. If you import a mixed options export, review the preview and archive non-swing trades so they don't consume the swing risk budget. The archived source data remains available for audit and backup.
- **FX:** The app can request a Bank of Canada reference FX rate from the optional Vercel `/api/fx` endpoint or accept a manually entered IBKR broker rate. The default 1.40 is *illustrative*. Calculated CAD P/L is an estimate unless overridden with the actual verified broker CAD net figure. Price, fees and original source fields remain preserved.
- **Risk:** The 70% stress reserve is not a guaranteed stop. Full option debit remains possible max loss. Current v2.0 accounting nets partial exits within a single position/attempt over the same rolling window; unrelated trade profits do **not** offset losing attempts. Partial exits also release the proportionate open reserve. A winning partial can age out before its losing runner, causing a later temporary increase in the rolling loss charge. Strict mode reserves full premium. Nothing sends orders to IBKR.
- **No master changes:** The app is not wired to edit your connected Google Sheet. Uploading an app backup to ChatGPT is the supported reconciliation handoff. No user data is automatically published to the hosting repository.

## v1.9: Per-portfolio estimated IBKR option fees

The defaults use USD 0.77/contract BUY and USD 1.00/contract SELL as **editable planning estimates**, not a guaranteed IBKR schedule or verified sell rate. Different exchanges, option classes and sell-side fees can change actual charges. Keep broker CSV commissions exact (4 decimal places). Never publish private broker account numbers or raw transaction exports in source control.

Each portfolio can change its BUY and SELL estimates under Rules & data -> Portfolio settings. New position, Add contracts, and Record exit dialogs prefill *total order fee* from quantity, and adjust on quantity changes until the user manually overrides the fee; Use estimate restores auto-fill. Quick-size draft fees follow quantity unless manually edited; the Auto button resets the draft. Estimates are flagged on newly recorded manual transactions. A unique matching IBKR CSV record supersedes a flagged estimate with the broker's actual fee and preserves the estimated value in provenance. Duplicate/ambiguous transactions remain protected. Fee defaults are stored with portfolio settings in local JSON, cloud sync and full backups; historical real fills are never recalculated when fee settings change.
